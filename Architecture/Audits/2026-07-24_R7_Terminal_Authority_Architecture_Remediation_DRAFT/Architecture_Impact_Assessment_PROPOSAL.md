# Architecture Impact Assessment — proposal only

This is an uninstalled proposal. It neither changes canonical architecture nor establishes acceptance. All sixteen independent-review blockers remain partial pending host transition, live adversarial proof, matrix execution, and independent review.

## Proposed architecture

1. **Exact clause authority.** Requirements identify immutable commit, blob, path, heading, exact range/text, and clause SHA-256. The current static graph contains 79 requirements, 151 cases, and 151 expectations with zero declared authority gaps. Generated artifacts remain subordinate to exact governing bytes.
2. **Independent cases and expectations.** Separate scripts and schemas construct cases and expectations. Producers receive no expected status/code/evidence. Proposed fixed-root ACLs deny execution and observation access to expectations; this OS proof is pending installation.
3. **Hostile outer execution.** Cases address terminal submission, candidate/fresh execution, retrieval, verification, lookup, reconciliation, retry/replay, failures, upgrade/history, and recovery. `POS-005` and `POS-006` use complementary nested outer submissions, not fixture summaries. No live outer execution occurred in the static unit.
4. **Signer-side semantics.** Children may submit raw evidence only. The signer proposal resolves OS caller/process/token, exact canonical frames, held files, ledger/receipt state, effects, version, transaction, recovery, and complete trace before disposition. Recovery results receive independent public rederivation by `R7RecoveryProbeAuditor`.
5. **Five-principal topology.** Terminal signer, execution, observation, comparator, and upgrade authority use separate proposed restricted service SIDs. The installation design applies LSA interactive/remote-interactive logon denials, a `SeChangeNotifyPrivilege` allowlist, narrow pipes, and disjoint key/store rights. These controls are source design, not current host fact.
6. **Canonical IPC.** A complete 12-byte framed protocol permits exactly one canonical NFC UTF-8 JSON payload, exact types and schemas, recursive duplicate rejection, and a 65,536-byte frame bound.
7. **Non-circular upgrades.** A separate operation-specific upgrade authority must sign the exact component transition before installation. Activation, nonce use, anti-downgrade state, revocation, rollback, trust history, and public verification are append-only. No upgrade transition was attempted.
8. **Version-aware history.** The verifier proposal preserves original trust and issuance rules and classifies authoritative, rejected, superseded, aborted, incomplete, revoked, and unverifiable evidence without rewriting receipts. Static sequence 332/678 classifications still require signed append-only host records.
9. **Transactional durability.** Explicit reservation, validation, preparation, commit, response, abort, supersession, and recovery states make retries and reconstructed responses deterministic. Disposable offline tests cannot replace live crash/restart proof.
10. **Physical identity.** Held no-follow handles bind final NT path, root/volume/file ID, owner/DACL, link count, ADS, canonical case/alias, size, bytes, and rename resistance. Future external utilities use the measured-invocation wrapper. Installed path attacks remain pending.
11. **Dependency and binary closure.** Fifteen governed scripts and all classified external utilities use fixed identities and absolute paths. Twelve executable roles have explicit source sets and two-pass raw/normalized identities. Python and runtime Git are removed; build/verification Git and PowerShell are measured nonauthority inputs. Live runtime-module and installed-process closure remains pending.
12. **Traceability and reconciliation.** Forward rows connect clauses through public verification/reconciliation; reverse rows cover every source, script, external utility, executable role, principal, case, and expectation. Host artifacts, live receipts/ledger entries, and matrix evidence will be added only after they exist.

## Failure and restart behavior

Malformed/noncanonical frames fail before dispatch. Missing authority, expected raw evidence, held-file identity, policy/version, authorization, dependency, or legal transaction transition fails closed. Precommit failures cannot become authority; a committed response is reconstructed from durable signed state. Stale or damaged checkpoints are classified and replayed without rewriting ledger entries. These are proposed semantics plus disposable static proof, not live service proof.

## Operational obligations and limitations

Future operators must preserve both ledgers and all failed/successful evidence, rebuild after any bound input changes, obtain authorization before installation, keep principals noninteractive and least-privileged, run stopped-service public verification and restart recovery, and never treat rejected history as authority.

The design relies on the measured Windows/NTFS/CNG/CLR boundary and excludes kernel, offline/elevated administrator, physical, firmware, TPM, HSM, and remote-signer protection. Static hashes do not prove an installed ACL, principal, key, service, runtime load set, or live side effect. Acceptance remains solely a later independent-review decision.
